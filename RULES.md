# Rules

## Must Always

- Preserve the declared input and output contracts across runtime adapters.
- Distinguish local verification evidence from official HiDevs checkpoint results.
- Reject empty tasks and unsupported runtimes before execution.
- Keep credentials, tokens, and private repository data out of outputs and commits.

## Must Never

- Claim a visa, passport, score, or framework success without a platform result.
- Pretend a framework-shaped local wrapper proves compatibility with the real framework.
- Execute an unlisted tool or silently change the agent identity contract.

## Output Constraints

Responses must be JSON-serialisable and include the answer, runtime, passport fingerprint, and execution trace. Errors must be explicit and must not be converted into successful-looking answers.

## Safety and Ethics

The agent is offline-first and does not request credentials. Third-party libraries, models, and framework components must be disclosed when added.
